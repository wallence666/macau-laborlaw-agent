# Agent 契約

第一版由單一 Python 工作流實作 A0-A8，角色之間只交換 `CaseState` 與結構化 `AgentHandoff`，不使用自由文字作為介面。

## 角色

| 角色 | 責任 |
| --- | --- |
| A0 | 管理順序、案件角色鎖定、停止與升級 |
| A1 | 判斷角色、議題與最少必要事實 |
| A2 | 產生不含虛構條號的檢索查詢 |
| A3 | 只從已審核法源取得證據並回傳版本資訊 |
| A4 | 只把實際證據轉成可驗證主張，不引入新法源 |
| A5 | 驗證來源、條號、引文、版本與生效日期 |
| A6 | 檢查高風險、證據不足、衝突與禁止行為 |
| A7 | 依狀態與角色組裝結構化回答 |
| A8 | 記錄測試、來源 ID、未解風險與 `trace_id` |

## 交接規則

- 每次交接都有 `trace_id`、來源角色、目標角色、狀態、產出欄位、測試與風險。
- A5 可以把引用失敗的主張設為不接受。
- A6 的 blocker 會阻止 A7 產出法律分析。
- 任何一步發現法域、版本、權限或角色衝突時，A0 必須停止並升級。
- 同一個 `case_id` 一旦鎖定使用者角色，不得在同一案件切換僱員與僱主角色。

## 模型交接

啟用 LLM 後，模型只作為 A1、A2、A4 的推理元件：

- A1/A2 回傳結構化事實、議題與檢索查詢，不生成法條編號。
- A4 回傳每條 statement 對應的 evidence ID 與精確 quote。
- A5 仍逐字驗證 quote，失敗即阻止回答。
- A3、A5、A6 不把最終控制權交給模型。

## 有限分析

使用者可選擇以目前資料繼續分析。此時 A0 不因 `missing_facts` 停止，但：

- A4 必須把未提供事實列入 uncertainties，不得補造。
- A6 會加入 `partial_analysis` 中級風險提示。
- 回答會標示為有限分析，並保留缺少事實清單。
- 高風險、引用失敗、版本衝突或來源不足仍會阻止回答。

## 案件結案與歷史

- `close_case(case_id)` 會解除 A0 在同一個案件中的角色鎖定與記憶體狀態。
- UI 的「問題已解決」會建立新的 `case_id`，避免下一個問題沿用舊事實與回答。
- 歷史紀錄由瀏覽器本地保存，只記錄問題、狀態、摘要、條號、模型名稱與 `trace_id`。
- 歷史紀錄不包含 API Key、完整案件事實或完整法源引用。

## 狀態

`CaseState` 包含案件、事實、欠缺事實、檢索查詢、證據、法律主張、引用檢查、風險、升級、回答、交接紀錄、審計測試與追溯 ID。完整欄位定義見 `src/laborlaw_agent/models.py`。
